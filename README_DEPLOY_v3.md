## 0. 이 번들이 합친 것

1. 토큰 리포트 링크: 새로 만드는 링크는 `report.html?student=학교-이름-토큰8자`. 이미 배포된 무토큰 링크도 계속 동작합니다(레거시 호환). 토큰이 붙어 있는데 틀린 경우에만 차단.
2. 개인정보 게이트: 키 없는 전체 조회 차단, roster/pending/absentees/exclude/명단저장/메일발송은 관리자 코드 필수. index 반 패널은 익명 집계(action=cohortmis)만 사용.
3. 조준모의고사 화학 I 숙제: 1페이지 OMR(별도 PDF, 인쇄용) 제출 -> hw_grader.html 에서 일괄 입력 -> 리포트의 [숙제 제출 · 피드백 보기] 버튼. OX 워밍업은 해설지 자가채점(디지털 미수집).
4. home.html 신규 랜딩(구세대 링크 제거), exam.html 반 명단 드롭다운, report 엔진 학교명 정규화 동기화.
5-2. 미응시자 오프라인 인쇄 (2026-07-07 추가): pending.html 에서 반별로 미응시자 시험지/재시지를 ZIP 다운로드(이름.pdf). 시험 미응시자는 그 회차 시험지, 재시 미응시자는 각자 개인화 재시지. 재시 수기 입력 페이지(retake_entry.html)에서 종이 재시 결과를 60 O/X 로 입력하면 자동 채점·진단되어 리포트에 재시로 반영. 재시는 결정적으로 재생성되므로 인쇄본과 채점본이 정확히 일치.
5-1. 시험지·해설 PDF (2026-07-07 추가): 회차 데이터로 시험지(문제만)와 해설(정답·바로잡기·해설)을 원클릭 .pdf 로 생성. 정시 + 재시 3버전 모두. 버튼 위치 = 응시 화면(exam), 성적표 회차 카드(report), 관리자 일괄 페이지(pdfs.html). 새 파일 pdfgen.js 가 엔진(클릭 시 라이브러리 지연 로드, 브라우저 렌더를 이미지로 캡처해 한글·화학식 정확, 문항 단위 페이지 분할).
5. pending.html 에 "시험 미응시" 섹션 추가: roster 미응시자(정식 시험 자체를 안 본 학생)를 반별로 보여주고, 온라인 응시 안내 카톡을 학생별(1차/리마인드) + 반 전체 공지로 복사. 링크는 응시 페이지(exam.html?c=&r=).

주의: 헤더 행이 신 순서라도 데이터 행은 다를 수 있습니다(새 코드가 헤더만 자동 갱신하기 때문). 판단은 데이터 행 기준으로 하고, 확실치 않으면 3)의 reorderColumnsToNew 를 그냥 실행하세요. 행별 자동 감지 + 멱등이라 이미 신 순서인 행은 건드리지 않습니다.

## 1. 배포 순서 (응시 없는 시간에 1~4를 한 호흡으로)

1) Apps Script: 시트 > 확장 프로그램 > Apps Script > 기존 코드 전체 삭제 후 `apps-script.gs` 붙여넣기 > 저장
2) 스크립트 속성: 현재 전체 공개 모드라 `ADMIN_TOKEN`/`STUDENT_CODE` 는 없어도 됩니다(있어도 무시됨). 나중에 토큰을 다시 켤 때만 5절 참고해 설정.
3) 편집기에서 `reorderColumnsToNew` 1회 실행 -> 데이터 행의 열 배열을 신 순서로 정규화합니다.
   - 행마다 배열을 자동 감지하므로 여러 세대가 섞여 있어도 안전하고, 이미 신 순서인 행은 건드리지 않습니다(멱등: 여러 번 실행해도 결과 동일). 실행 로그에서 변환 행 수를 확인하세요.
   - 이 단계를 건너뛴 채 새 백엔드가 구 배열 데이터를 읽으면, 서버가 학생을 못 찾아 모든 리포트가 데모 인물(조민수)로 표시됩니다.
4) 배포 > 배포 관리 > 연필(편집) > 버전: **새 버전** > 배포
   - 절대 "새 배포"를 만들지 않습니다. /exec URL이 바뀌어 전 링크가 깨집니다.
   - 편집기에 코드를 저장만 하면 라이브에 반영되지 않습니다. 새 버전 배포까지 해야 /exec 이 새 코드로 동작합니다.
5) 저장소 /DT/ 에 웹 파일 업로드(아래 표) 후 push. index.html 을 올릴 때는 chemengine.js 를 반드시 함께 올립니다(엔진을 외부 파일로 분리했기 때문에, 없으면 채점·진단이 동작하지 않습니다). GitHub Pages 반영(~1분)까지가 유일한 전환 창입니다.
6) 트리거 확인(편집기 좌측 시계 아이콘): `onEditSync`(시트 편집), `weeklyPendingEmail`(수 18시), `weeklyAbsenteeEmail`(월 18시), 선택 `applySheetColors`(매일 6시). 없는 항목은 대응 setup 함수를 1회 실행.
7) 이미 공유된 무토큰 링크는 그대로 계속 동작합니다(재공유 불필요). 새로 공유할 때는 시트 B열 링크를 쓰고, 선택 사항으로 `resyncAllKeysLinks` 를 1회 실행하면 B열 링크가 전부 토큰 링크로 갱신됩니다(3의 정규화 이후에만 실행).

## 4-1. 미응시 관리 (pending.html)

pending.html 은 두 종류를 한 화면에서 관리합니다.
- 시험 미응시(상단): 정식 시험 자체를 아직 안 본 학생. roster 명단과 시트 응시 기록을 대조해 반별로 표시. 학생별 [1차 안내]/[리마인드], 반 단체방용 [반 전체 공지] 복사. 안내 링크는 해당 회차 응시 페이지로 바로 연결됩니다.
- 재시 미응시(하단): 미통과 후 재시를 안 본 학생(기존 3단계 카톡).
- 미응시 명단의 회차는 roster 의 반별 설정(또는 최근 8일 내 채점된 회차)을 따릅니다. 특정 회차로 고정하려면 roster 에서 반의 회차를 지정하세요.

- 비밀번호 변경: index.html 의 `adminGate()` 안 `'0000'` 을 원하는 값으로 바꾸고, head 조기 스크립트는 그대로 두면 됩니다. 이미 통과한 기기에서 다시 묻게 하려면 그 기기에서 localStorage 의 `dt_admgate` 를 지우면 됩니다(개발자도구 > Application > Local Storage).

1. apps-script.gs 의 `adminOk_` 를 한 줄로 교체: `function adminOk_(t) { var need = adminToken_(); return need !== '' && String(t || '').trim() === need; }`

3. 스크립트 속성 `ADMIN_TOKEN`(관리자), `STUDENT_CODE`(반 코드) 설정 -> 새 버전 재배포.
(원래 코드가 필요하면 이전 번들의 해당 파일을 참고하세요.)
